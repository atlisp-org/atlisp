# @lisp 决策规则配置

## 一、任务分类规则

### 任务类型识别

| 关键词 | 任务类型 | 处理方式 |
|--------|----------|----------|
| 修复、bug、错误、问题 | Bug修复 | 执行bug-fix流程 |
| 添加、新建、创建、实现 | 新功能 | 执行new-function流程 |
| 审查、检查、review | 代码审查 | 执行code-review流程 |
| 更新、修改、优化 | 代码优化 | 执行code-review流程 |
| 同步、拉取、更新 | 同步操作 | 执行sync-all |
| 测试、验证 | 测试任务 | 执行test流程 |
| 文档、说明、README | 文档任务 | 执行文档更新流程 |

## 二、优先级判断规则

### 优先级定义

| 级别 | 条件 | 响应时间 |
|------|------|----------|
| **P0 紧急** | 生产环境崩溃、数据丢失、安全漏洞 | 立即处理 |
| **P1 高** | 核心功能异常、影响用户使用 | 2小时内 |
| **P2 中** | 非核心功能异常、有 workaround | 24小时内 |
| **P3 低** | 体验问题、文档错误、代码规范 | 一周内 |

### 自动判断规则

```
IF 问题描述包含 "崩溃" OR "数据丢失" OR "安全" THEN
    优先级 = P0
    
ELSE IF 问题描述包含 "核心功能" OR "无法使用" THEN
    优先级 = P1
    
ELSE IF 问题描述包含 "异常" OR "错误" OR "bug" THEN
    优先级 = P2
    
ELSE IF 问题描述包含 "建议" OR "优化" OR "改进" THEN
    优先级 = P3
```

## 三、处理决策规则

### 代码修改决策

```
IF 修改范围 < 10行 THEN
    直接修改，无需评审
    
ELSE IF 修改范围 10-50行 THEN
    修改后运行测试，确认无误
    
ELSE IF 修改范围 > 50行 THEN
    分步修改，每步验证
    生成修改报告
```

### 错误处理决策

```
IF 错误类型 = "语法错误" THEN
    直接修复，运行 lint 验证
    
ELSE IF 错误类型 = "逻辑错误" THEN
    分析原因，设计测试用例
    修复后运行完整测试
    
ELSE IF 错误类型 = "运行时错误" THEN
    添加错误处理
    记录错误日志
    通知相关人员
```

### 测试决策

```
IF 新增函数 THEN
    必须添加单元测试
    
ELSE IF 修改函数 THEN
    运行现有测试
    添加回归测试
    
ELSE IF 重构代码 THEN
    运行所有测试
    确保行为不变
```

## 四、资源分配规则

### 时间分配

| 任务类型 | 分配时间 | 超时处理 |
|----------|----------|----------|
| Bug修复 | 2小时 | 升级处理 |
| 新功能 | 4小时 | 分步实施 |
| 代码审查 | 1小时 | 简化审查 |
| 文档更新 | 30分钟 | 简化更新 |

### 工具使用决策

```
IF 任务涉及多个文件 THEN
    使用 make 命令批量处理
    
ELSE IF 任务涉及单个文件 THEN
    直接编辑文件
    
IF 任务涉及代码检查 THEN
    使用 make lint
    
IF 任务涉及测试 THEN
    使用 make test
```

## 五、质量控制规则

### 代码质量门禁

```
IF lint 检查有 error THEN
    必须修复后才能提交
    
IF lint 检查有 warning THEN
    建议修复，不强制
    
IF 测试失败 THEN
    必须修复后才能提交
```

### 文档质量门禁

```
IF 新增函数 THEN
    必须有 docstring
    
IF 新增包 THEN
    必须有 README
    
IF 重大变更 THEN
    必须更新 CHANGELOG
```

## 六、异常处理规则

### 异常分类

| 异常类型 | 处理方式 |
|----------|----------|
| 网络异常 | 重试3次，失败后记录日志 |
| 权限异常 | 提示用户，请求权限 |
| 资源异常 | 释放资源，记录日志 |
| 逻辑异常 | 分析原因，修复代码 |

### 异常升级规则

```
IF 异常次数 > 3 THEN
    升级为高级异常
    通知维护人员
    
IF 异常影响 > 10用户 THEN
    立即升级处理
    启动应急预案
```

## 七、沟通决策规则

### 汇报决策

```
IF 任务完成 THEN
    生成完成报告
    
IF 任务阻塞 THEN
    立即汇报，说明原因
    
IF 发现新问题 THEN
    记录问题，评估优先级
```

### 协作决策

```
IF 任务需要其他模块 THEN
    协调相关负责人
    
IF 任务需要外部资源 THEN
    申请资源，等待审批
```

---

*遵循这些规则，确保决策的一致性和合理性。*
