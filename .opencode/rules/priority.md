# @lisp 优先级判断配置

## 一、优先级定义

### P0 - 紧急
```
条件:
- 生产环境崩溃
- 数据丢失或损坏
- 安全漏洞被利用
- 核心服务完全不可用

响应时间: 立即处理
处理方式: 启动应急预案，全员通知
```

### P1 - 高
```
条件:
- 核心功能异常
- 影响用户正常使用
- 有数据风险
- 安全隐患

响应时间: 2小时内
处理方式: 优先处理，专人负责
```

### P2 - 中
```
条件:
- 非核心功能异常
- 有 workaround
- 性能问题
- 兼容性问题

响应时间: 24小时内
处理方式: 正常处理，排期解决
```

### P3 - 低
```
条件:
- 体验问题
- 文档错误
- 代码规范
- 优化建议

响应时间: 一周内
处理方式: 有空处理，批量解决
```

## 二、自动判断规则

### 关键词匹配

```
P0 关键词:
- 崩溃、crash、down
- 数据丢失、data loss
- 安全、security、漏洞
- 不可用、unavailable

P1 关键词:
- 核心功能、core
- 无法使用、cannot use
- 重要、important
- 紧急、urgent

P2 关键词:
- 异常、error、bug
- 错误、mistake
- 问题、issue
- 性能、performance

P3 关键词:
- 建议、suggestion
- 优化、optimize
- 改进、improve
- 文档、document
```

### 评分系统

```
影响范围 (0-10分):
- 影响所有用户: 10分
- 影响部分用户: 5分
- 影响单个用户: 1分
- 无影响: 0分

严重程度 (0-10分):
- 完全不可用: 10分
- 功能严重受损: 7分
- 功能部分受损: 4分
- 轻微影响: 1分
- 无影响: 0分

紧急程度 (0-10分):
- 需立即处理: 10分
- 需尽快处理: 7分
- 需按时处理: 4分
- 可延后处理: 1分
- 无时间要求: 0分

总分 = 影响范围 + 严重程度 + 紧急程度
P0: ≥ 25分
P1: 18-24分
P2: 10-17分
P3: < 10分
```

## 三、动态调整规则

### 升级条件

```
IF 任务超时 THEN
    优先级 + 1
    
IF 问题扩散 THEN
    优先级 + 1
    
IF 用户投诉增加 THEN
    优先级 + 1
```

### 降级条件

```
IF 问题已缓解 THEN
    优先级 - 1
    
IF 有 workaround THEN
    优先级 - 1
    
IF 用户不再关注 THEN
    优先级 - 1
```
